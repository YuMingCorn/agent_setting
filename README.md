# Agent settings for Claude Code, Codex and Antigravity CLI

My custom subagents and skills. They were written for Claude Code, and the repo also ships generated versions for Codex and Antigravity CLI (`agy`), so some jobs can be handed to those tools.

## Quick start

Windows, all three tools at once:

```powershell
git clone https://github.com/YuMingCorn/agent_setting.git
cd agent_setting
powershell -ExecutionPolicy Bypass -File .\deploy.ps1 -All
```

macOS or Linux (Codex as the example):

```sh
git clone https://github.com/YuMingCorn/agent_setting.git
cd agent_setting
mkdir -p ~/.agents/skills ~/.codex/agents
cp -R portable/skills/* ~/.agents/skills/
cp portable/codex/agents/* ~/.codex/agents/
```

Restart the tool, then type `/reframe <your request>` in Claude Code to try it. To install for one tool only, copy these folders:

| Tool | Copy | To |
|---|---|---|
| Claude Code | `agents/*`, `skills/*`, `tools/*` | `~/.claude/agents/`, `~/.claude/skills/`, `~/.claude/tools/` |
| Codex | `portable/skills/*`, `portable/codex/agents/*` | `~/.agents/skills/`, `~/.codex/agents/` |
| Antigravity CLI | `portable/skills/*`, `portable/antigravity/agents/*` | `~/.agents/skills/` (or `~/.gemini/config/skills/`), `~/.gemini/config/agents/` |

## Contents

| Path | What it holds |
|---|---|
| `agents/` | 8 subagents in Claude Code format. **Source of truth.** |
| `skills/` | 7 skills in Claude Code format. **Source of truth.** |
| `tools/` | Scripts that agents call, such as `agy_run.py`. Deployed to `~/.claude/tools/`. |
| `portable/` | Codex and Antigravity CLI agents (all but `agy-runner`), and 5 skills in the [Agent Skills](https://agentskills.io/specification) format, all generated by `build.ps1`. Never edit by hand. |
| `build.ps1` | Generates `portable/` from `agents/` and `skills/`. |
| `deploy.ps1` | Copies the files into your home folder. |
| `check.ps1` | Checks the repo before a commit. |
| `backup.ps1` | Copies direct edits in `~/.claude` back into the repo. |

## Agents

Subagents that the main agent starts by type of job: Haiku for mechanical work, Sonnet for search and checks that need judgment, Opus for building.

| Agent | Model | Tools | Use it for |
|---|---|---|---|
| `haiku-explore` | Haiku | Read, Grep, Glob | Local search with a known target. Returns `path:line`. |
| `sonnet-search` | Sonnet | Read, Grep, Glob | Local search that needs judgment, such as tracing links across files. |
| `sonnet-web` | Sonnet | WebSearch, WebFetch | Web lookups of docs, APIs and versions, each claim with its URL and date. |
| `haiku-audit` | Haiku | Read, Grep, Glob | Checks many files against an explicit checklist and reports violations only. |
| `haiku-worker` | Haiku | All | Repetitive work whose results are easy to check. Not for code. |
| `opus-builder` | Opus | All | Builds from a clear brief after the plan is decided, and reports changes file by file. |
| `sonnet-checker` | Sonnet | Read, Grep, Glob, Bash | Checks finished work against its brief and ends with `PASS` or `FAIL`. |
| `agy-runner` | Haiku | Read, Bash | Claude Code only. Hands a written task to Antigravity CLI (`agy`) and reports what it changed. Only when you ask for agy. |

The Codex and Antigravity CLI versions differ in these ways:

- They set no model, so each agent uses the main session's model.
- Antigravity CLI tool names are translated, for example `Read` to `read_file`. Its custom agents get no search tools, so `Grep` and `Glob` become `run_command` (search runs as a shell command), and `WebFetch` becomes `search_web`. An agent without a `tools` line gets an explicit full list, because Antigravity gives such an agent only a small read-only set.
- Codex cannot limit tools, so "read-only" and "local only or web only" rest on the instructions alone. In Antigravity CLI, "read-only" also rests on the instructions, because the search agents need `run_command`.

### `agy-runner` (Claude Code only)

The main agent writes the task to a file, and `agy-runner` runs `tools/agy_run.py`. The script picks a model by task type (`read`, `rewrite`, `simple`), skips quota groups you say are used up, and talks to `agy acp` so that it can answer each permission request itself:

- File writes are allowed only in the `--write` folders. With no `--write`, the task is read-only.
- Shell commands are allowed only when they start with an `--allow-cmd` prefix and use no quotes, pipes or `..`.
- At the end it lists the files that changed inside and outside the write folders.

What it cannot limit, as tested with agy 1.5.18 on 2026-11-26: agy reads any file without asking, `.env` files too. It also approves writes into the system temp folder by itself, so the script refuses a project in the temp folder. Plain `agy -p` is not used, because in that mode agy writes files anywhere with no prompt.

## Skills

| Skill | Tools | What it does |
|---|---|---|
| `/reframe` | Claude Code, Codex, Antigravity CLI | Gets the problem right before work starts, and rewrites the request. |
| `/sharpen` | Claude Code, Codex, Antigravity CLI | Raises the method and checks to expert level, and rewrites the prompt. |
| `/restate` | Claude Code, Codex, Antigravity CLI | Restates your goal in its own words and asks questions. |
| `/first-principle` | Claude Code, Codex, Antigravity CLI | Reduces a problem to axioms and rebuilds the solution from them. |
| `/wrap-up` | Claude Code, Codex, Antigravity CLI | Ends a session: checks, commits and gives a recap. |
| `/session-review` | Claude Code only | Reviews recent sessions and proposes skills, scripts or rules. |
| `/brain` | Claude Code only | Plans a big job with Fable and hands the parts to the agents. |

How to call a skill: type `/name` in Claude Code and Antigravity CLI, and `$name` in Codex. Every skill runs only when you call it by name. Claude Code enforces this with `disable-model-invocation: true`, and Codex with the generated `agents/openai.yaml`. Antigravity CLI has no such setting, so there the description only asks the model not to start the skill on its own.

### `/reframe`

```
/reframe [the request to clarify]
```

Gets the problem right, and stated right, before any work starts. It reads the source material, picks a reading of the request, and collects 8 to 12 key terms (each with a checked source), ideas from nearby fields and missing constraints. It ends with a rewritten request for an agent, and builds nothing.

### `/sharpen`

```
/sharpen [the request to deepen, usually the output of /reframe]
```

Raises the method to the level of the best people in the field. It tests technical choices with a small experiment before it recommends one, and leaves product trade-offs to you. It accepts only outside evidence, such as tests or benchmarks, and ends with a prompt that an agent can run. Suggested order: `/reframe`, then `/sharpen`, then build.

### `/restate`

```
/restate [the task to restate; default: your latest request]
```

Before any work starts, says in its own words your goal, your problem and the guesses it made. Then it lists questions with default answers and waits for you. It only reads files in that turn and changes nothing.

### `/first-principle`

```
/first-principle [the problem to think through; default: your latest request]
```

Sorts the assumptions behind the usual solution into axioms, conventions and unverified beliefs. It rebuilds the solution from the axioms alone and states the risk of each change compared with the usual way. It checks facts by reading code or measuring, not from memory.

### `/wrap-up`

```
/wrap-up [push | pr] [notes for the recap]
```

Ends a session: unchecked changes go to `sonnet-checker` first, then it commits this session's files one by one and gives a recap that lists unfinished work. It pushes or opens a pull request only when you write `push` or `pr`. It never force-pushes, merges or deletes a branch.

### `/session-review` (Claude Code only)

```
/session-review [days, default 30] [project name filter]
```

Reads the transcripts in `~/.claude/projects/` to find what you want to be told, which questions you did not need to be asked, and what in the current project could become a skill, script or rule. It reads earlier reviews and your existing rules first, so it does not propose again what you declined or what a rule already covers. It only proposes numbered changes, and builds nothing until you pick. Run its script with `uv run --no-project python`.

### `/brain` (Claude Code only)

```
/brain <the job and what done means>
```

Fable (high effort) plans and splits a big job, delegates to the agents above only when that pays off, and has `sonnet-checker` check the result before it calls the job done. It depends on Claude-only models and features, so it is not in `portable/`.

## Maintaining this repo

1. Edit `agents/` or `skills/`, then run `build.ps1` to regenerate `portable/`.
2. Run `check.ps1`. It checks that each agent's name matches its file, that each skill's name matches its folder and has `disable-model-invocation: true`, that both READMEs list every agent and skill with the right counts, that `portable/` has no changes left to commit after a build, and that the `.ps1` files are ASCII-only. It ends with `PASS` or `FAIL`.
3. Preview, then deploy (leave out `-All` to deploy to Claude Code only):
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\deploy.ps1 -All -DryRun
   powershell -ExecutionPolicy Bypass -File .\deploy.ps1 -All
   ```
   It first saves the current copies to `%TEMP%\claude-deploy-backup\`, and never touches `~/.claude/skills/synced/`. Before copying, it compares your home folder with the repo:
   - If a file is newer at home, it stops, so that a direct edit is not lost. Run `backup.ps1` first, or add `-Force` to overwrite.
   - It lists old files: files that were in the repo at some point (in the git history) and are gone now, but still exist at home. It deletes them only with `-Prune`. Files that the repo never had are never touched.
4. Commit and push.

If you changed files directly in `~/.claude` (`agents`, `skills` or `tools`), run `backup.ps1` and then `build.ps1`. `backup.ps1` mirrors with `robocopy /MIR`, so a file you deleted in `~/.claude` is also deleted in the repo.

## Notes

- The Claude Code files are tested. The Antigravity CLI agent format and tool names were checked against `agy` on 2026-11-26. The Codex files follow the official docs but have not been run yet.
- The scripts run on Windows only (PowerShell 5.1 and `robocopy`) and use ASCII characters only, so that PowerShell 5.1 reads them in any code page.
- For Antigravity CLI, `build.ps1` lowercases agent names and stops with an error on any character other than lowercase letters, digits, `-` and `_`.
- `.gitattributes` keeps LF line endings.
